# 双语字幕窗口原型

本页回答：196逻辑点宽的小窗，如何协调原文、译文与音源提示；展开后如何阅读两路历史。仅使用模拟文本，不录音、不调用翻译服务、不保存业务内容。

在这个原型分支运行：

```sh
python3 Prototypes/GUI/serve.py --port 8766
```

打开 `http://127.0.0.1:8766/?study=bilingual&variant=A`，底部可切换A/B/C，也可用左右方向键。默认暂停并显示完整示例，演示控制可继续出字、切换中英/长句/翻译等待、独立功能开关、目标语言及音源识别模式。

| 方案 | 布局 | 当前固定示例实测 |
| --- | --- | --- |
| A 轻叠字幕 | 控制栏、来源、原文、译文依次排列 | 196×106，长句最高约120 |
| B 紧凑胶囊 | 计时与来源同一行，字幕用紧凑语言标识 | 196×89 |
| C 音源侧栏 | 独立电平侧栏与当前音源字幕 | 196×106 |

展开统一380×320，支持音源筛选。两项字幕功能都关闭时A缩至196×39。尺寸为当前示例的CSS逻辑点，文本与状态会改变高度，不按截图像素倍率推断真实App尺寸。

设计初稿由Antigravity（Gemini3.8 Flash High）完成，主agent修正了浅色样式、会议背景、控件遮挡、完整句预览、目标语言与仅译文状态。浏览器验证了三方案宽度、四种开关组合、长句、等待、目标语言跳过、pin状态保留、展开与历史音源筛选。尚未选定最终布局；截图/模拟交互不能证明真实识别、翻译、覆盖保存或系统置顶行为。

关联：[验证双音源双语字幕在大小悬浮窗中的展示](https://github.com/patrick-fu/meetingtape/issues/23)。本分支是可丢弃原型，不直接合并到生产。
