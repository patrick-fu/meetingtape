# Keep the session through device changes and system sleep

MeetingTape targets system audio across all output devices and follows the macOS default microphone, rebuilding capture automatically when the input changes. A session prevents idle system sleep while allowing lock and display sleep; actual system sleep suspends capture, and wake resumes the same session. This keeps a meeting in one recording without requiring a new start command, while public pause/resume commands remain out of scope.

The user confirmed this policy on 2026-10-23 for [#7](https://github.com/patrick-fu/meetingtape/issues/7), after the [Doubao reference check](../research/doubao-capture-behavior.md). Doubao's packaged recorder implements system-triggered pause/resume, but its all-output-device scope and current microphone selection defaults remain unverified; those are MeetingTape requirements, not claims of equivalent behavior.

The file preserves elapsed real time through capture interruptions, including system sleep, by inserting silence for unavailable audio and reporting the affected intervals. If one source fails, keep the other source and retry automatically; if both sources remain unavailable for more than 30 seconds while the system is awake, end with an error and preserve existing content. Valid silent audio is not a capture failure.

Crash or forced-termination recovery may retain recovery files, with a consumer-level acceptance target of losing at most the final five seconds of captured audio; normal finalization still produces one main stereo m4a. The user confirmed these interruption and preservation rules in the next grilling round. This is an implementation and validation requirement, not a guarantee already established by the current scaffold; [#8](https://github.com/patrick-fu/meetingtape/issues/8) must verify actual duration, recovered samples and failure reporting.

## Crash recovery storage and command

The user subsequently accepted sequential PCM CAF recovery storage and an explicit `recover` command on 2026-10-23. At 48 kHz, float32 stereo captured audio uses approximately 1.38 GB per hour; `--keep-raw` adds approximately 0.69 GB per hour for the raw microphone. These are temporary audio sizes, excluding metadata and the compressed output that coexists during finalization. Whole sleep gaps are represented by timeline metadata rather than stored PCM silence. The trade-off is predictable recoverable audio at the cost of temporary disk space; the [synthetic CAF probe](../research/caf-recovery.md) supports feasibility within its stated limits.

Normal use remains `start` and `stop`. After an abnormal exit, retained recovery materials and English help must make the explicit `recover` invocation discoverable. Recovery validates the session manifest and committed audio extent, then produces a new m4a without overwriting an existing recording. The required `--out` retains its existing writable-directory semantics. Recovery does not extend an unknown crash tail to the current time.

Remove temporary recovery materials only after validating all requested output files. Capture, checkpoint, encoding or recovery failure retains available recovery materials and reports failure with their location. This decision settles storage and invocation; it does not establish live recording support or the five-second loss bound. Those remain implementation and consumer-level acceptance requirements in #7 and #8.
