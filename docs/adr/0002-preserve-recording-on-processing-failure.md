# Preserve recording when speech processing fails

MeetingTape will first validate standalone WebRTC APM for local echo cancellation, noise suppression and digital automatic gain control; it will leave the system microphone volume unchanged. When speech processing explicitly fails but capture and writing remain available, recording continues with raw microphone audio in the right channel, with degraded intervals reported in status and session metadata. Lost meeting content cannot be recovered, so this deliberately relaxes the earlier guarantee that every right-channel sample has passed through 3A; an unrecoverable capture or writing failure ends the session with an error and preserves existing content where possible.

The system-audio channel remains available as the echo-cancellation reference, and `--keep-raw` retains its separate pre-3A microphone recording. The initial integration direction is an upstream static build and a C interface for Swift, supported by the [isolated build and interface validation](../research/apm-integration.md); production packaging, measured reference timing and real-recording quality remain validation gates. [Issue #6](https://github.com/patrick-fu/meetingtape/issues/6) records the decision; [issue #8](https://github.com/patrick-fu/meetingtape/issues/8) owns final recording acceptance.
