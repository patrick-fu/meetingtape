# 分音源、双语字幕与导出验收

2026-10-29。本轮沿用本地构建与验收流程，无 CI。实际语音测试只上传合成内容；既有用户录音和正在使用的 App 保持不动。

2026-10-30 补充用户选定的黑白字幕气泡图标及重新打包验收。

## 已验证

- Qwen 与 MOSS 对同一份约 7.45 秒合成双声道录音分别完成系统/麦克风四路识别，正文含独立音源，原音频 SHA-256 不变。实际 runner 记录了 CPU 时间、峰值 RSS、执行耗时；RSS 为单独进程，不包含 GPU 或整机。
- 豆包实时识别分别建立两路连接，接 Apple 本地文字翻译，取得两路定稿，保存后重载一致；仅翻译模式未保存独立原文。相同语音置于两路用于检查路由和归档，不证明说话人识别或声学干扰已解决。
- Apple 翻译语言包通过系统下载页安装，中英两向从 supported 变为 installed；实际生产适配器双向翻译及目标语言跳过通过。一次探针的两次 translate 调用约 0.80/0.12 秒，不能作为冷启动或连续字幕性能承诺。
- 原生 App 的导出选择器提供实时稿和三份录后稿；通过保存对话框取得一份主稿、三份展开附稿和运行明细。同参数下与包内 CLI UTF-8 输出逐字节一致。这里三份录后文字是明确标注的导出夹具，实时稿来自真实合成语音请求。
- 故障夹具覆盖 runner 退出 0 但结果缺失/损坏、合法空结果、单路失败后只重试失败路、已成功结果逐字节不变、已完成块续跑、旧 JSON 请求身份迁移、Markdown 转义、未知覆盖前缀及异步重试身份隔离。
- 额外复现并修复：成功任务丢失一路正文时，CLI、App 和导出明确呈现部分正文及缺失音源，不修改已有执行历史；短句已结束而另一音源长句继续更新时，小窗跟随最新结束时间，归档仍按开始时间排列。两项回归在修复前失败、修复后通过。
- 相邻读取回归已补齐：损坏一路正文不会吞掉另一条，完整稿损坏可回退到通过音源/修订校验的部分稿；已成功旧版本正文全部不可读时，不阻断独立完好主稿导出。附稿标明不可读取，失败任务仍可导出真实状态和统计，损坏文件与执行历史不改写。
- Debug/release App 与嵌套 helper 已用本地 Developer ID 编译签名并验证。Translation.framework 为弱链接，部署目标保持 14.2；本地实时文字翻译按 macOS 26 能力控制。
- 用户选定现代方案 F。保留内置生图工具的原始图片、提示词与 SHA，导出 1024 像素 sRGB 未裁角母图及 16–1024 像素多分辨率 ICNS；本轮明确允许 GPT Image 2，工具未返回实际模型字段，不声称已核验为 2.5。生成记录见 `Resources/Artwork/AppIcon-generation.json`。
- 最新 release App 的 `CFBundleIconFile` 正确指向包内 ICNS，其字节与仓库资源相同。Finder 实际显示新图标，隔离运行实例的系统图标读取正确，App 正常启动；重新构建的包内 helper 导出与此前原生 App 保存的 4776 字节 Markdown 仍完全一致。
- `b3097a9` 的隔离原生 App 使用包内 CLI 开启约 133.89 秒设备录音，实际操作展开、收起、取消/恢复置顶和悬浮窗停止；两路设备可用，文件保存入库。字幕开关关闭，录音没有上传；这不覆盖 App 直接启动录音的麦克风授权。
- 真实豆包协议合成对照：起点 0 与 7.51 秒、仅麦克风一次重连，四句公共时间起点差为 0、−30、+1、+10 毫秒；各连接服务时间加自身起点与保存重载后的归档精确一致，发送帧连续。这是复制生产路径的隔离协议验证，不是最终签名包，也不能确定历史单句约 7.398 秒分段差异的根因。
