# Markdown 导出契约

2026-10-29。决策稿，依据[导出与运行统计](https://github.com/patrick-fu/meetingtape/issues/20)、[分音源转写](https://github.com/patrick-fu/meetingtape/issues/19)与[字幕翻译规则](https://github.com/patrick-fu/meetingtape/issues/22)。本文和示例是实现依据，当前生产代码尚无 Markdown 导出器。

## 已确认的产品行为

- CLI 与 App 都支持导出 Markdown；默认导出用户选中的一份主稿。
- 用户开启“包含其他版本”后，附上实时稿及其他录后模型稿，分别放入 `<details>` 区块。不得将多个模型的文字自动拼成裁决稿。
- 主稿及附稿保留阶段、模型、识别模式与音源；每段使用相同录音时钟。系统音频/麦克风是音源，不是说话人身份。
- 关闭、掉线期间不自动补字幕；恢复后从当前继续。需要补齐时另建录后转写任务，并形成独立版本。
- 更改目标语言只作用于之后的新内容。旧译文保留原目标语言标签，不能被新语言覆盖。
- 运行统计用可展开明细，只呈现实测、采样或服务实际返回的数据。未记录写“未采集”，不能获得写“不可得”，均不按零处理；不估算费用或准确率。

## 格式与版本归属约束

这些约束用于落实原稿保留与真实来源，不另增加用户选择。

1. 同一录音、相同结果快照及选项，经 CLI/App 得到相同的 UTF-8 Markdown 正文；界面路径和本机绝对路径不写入稿件。
2. App 使用当前选中的主稿。CLI 明确指定主稿；如果存在多份可用稿件，不猜测哪一个模型更好。现有 JSON/纯文本输出继续可用。
3. 时间显示为相对录音起点的 `HH:MM:SS.mmm`；保留已有精度，缺失值标“时间未知”，不伪造毫秒或把连接起点冒充录音起点。
4. 分开识别的正文按时间排列并标音源；同时讲话保留重叠时间。合并识别与历史混音稿标“合并音源”，不伪造两路来源。
5. 每个展开区块是一份阶段/模型/识别模式明确的版本。其两路音源仍在共同时间轴上排列，单路失败不吞掉另一条已保存结果。
6. 译文只属于产生它的原文版本和语句。切换主稿不会把实时译文借用到另一个录后模型的正文。只有译文的区间不恢复内部原文。
7. 未完成、失败和取消的任务保留原状态及已取得的部分结果；未定稿文字标明“未定稿”，不当作完整成功稿。
8. 模型返回的文字按普通文本转义，不能闭合展开块或注入 HTML。正文中的换行、列表与 `<details>` 边界不得因原始模型文本损坏。

## 覆盖明细

覆盖区间要标明阶段、功能和音源，不能把“实时字幕未开启”当成“录音缺失”，也不能据此给另一份完整录后稿制造断档。

| 状态 | 导出含义 |
| --- | --- |
| 正常工作 | 在该区间启用，并有可追溯处理状态；无语音不编造正文 |
| 未开启转写 | 用户关闭原文转写；仅翻译可能继续依赖内部识别 |
| 未开启字幕翻译 | 用户关闭翻译；原文转写可能继续 |
| 连接/识别失败 | 功能原本启用，但该音源未得到结果，不写成“未开启” |
| 翻译失败 | 语音识别和录音可继续，标明缺少译文 |
| 目标语言，无需翻译 | 在转写开启的情形下只显示一份原文，不制造重复译文 |
| 仅翻译且已为目标语言 | 保留目标语言字幕一次，标明“无需翻译”，不另存重复的独立原稿 |
| 历史未记录 | 不知道当时的开关或资源状态，不能倒推为关闭或失败 |

区间采用起点包含、终点不包含的约定，按照录音公共时钟归属；功能开关与目标语言边界需保留。用户已确认仅翻译且原话已是目标语言时也保留字幕一次；“关闭转写”表示不保存一份额外的独立原稿，不表示丢弃这些目标语言字幕。

## 运行统计的范围

| 明细 | 采集和展示边界 |
| --- | --- |
| 状态、模型与音源 | 来自实际任务和版本记录，不能把部分失败汇总为成功 |
| 音频覆盖 | 本次实际处理的起止区间；覆盖长度不等于执行耗时 |
| 排队/执行/总耗时 | 有对应观测时才显示；实时执行可能包含等待新音频的时间，不能与录后耗时直接当作速度排名 |
| CPU 累计时间 | 注明测量进程/子进程范围；云端服务 CPU 不可由客户端 CPU 代替 |
| 峰值内存 | 注明单位、采样或实测以及进程范围；不冒充整机/GPU内存，也不把多路峰值相加当作整机峰值 |
| 云端用量 | 只列服务实际返回的单位和值；未返回时写“不可得”，不据音频长度估算账单 |

本地共享进程或运行时无法归属到单一模型的资源，不摊派出虚构的“每模型”指标。旧任务缺失统计不补算。
